# FleetOps MZ — frontend conventions

Read this before adding or changing a feature. **`src/app/features/vehicles/` is the reference
implementation** (list page, detail page with tabs, drawer form, status dialog, facade). Copy its
patterns rather than inventing new ones.

## Angular rules

- Angular 21, standalone components, zoneless, signals. `ChangeDetectionStrategy.OnPush` everywhere.
- Every component has separate `.ts`, `.html` and (when it needs styles) `.scss` files. No inline
  templates, no inline `styles`, no `style="…"` attributes (dynamic `[style.x]` bindings for data-driven
  values such as chart colours are fine).
- Class names have **no `Component` suffix**: `TripsPage`, `TripDetailPage`, `TripForm`.
- Use `input()`, `output()`, `model()`, `computed()`, `linkedSignal()`, `inject()`; control flow `@if/@for/@switch`.
- Route params and query params are bound to inputs (`withComponentInputBinding`):
  `readonly id = input.required<string>()`, `readonly status = input<string | undefined>()`.
- Reactive Forms (`NonNullableFormBuilder`) for data entry, with `<app-field-error [control]="…">`.
- No `any` (use `$any($event.target).value` only for DOM events in templates).
- Business calculations live in `core/domain/*` (pure, unit-tested) or a feature facade — never in templates.

## Folder layout

```
src/app/
  core/
    models/            typed domain models + enum arrays (VEHICLE_STATUSES, …)
    data-access/       repository contracts (repositories.ts), query helpers, createQuery()
    services/          mock-*.service.ts (mock repositories), EntityDirectory, FleetAnalytics,
                       TripWorkflowService, NotificationCenterService, ClockService, DemoDataService
    domain/            profitability, fuel analysis, trip rules, expiry & maintenance status
    formatting/        Intl formatters, currency (simulated rates), FormatService, pipes
    i18n/              TranslationService, `t` pipe, resources/<lang>/<feature>.ts
    state/             preferences, theme, company settings
    mock-data/         JSON fixtures (generated by tools/generate-mock-data.mjs — do not hand-edit)
  shared/
    ui/                reusable components (see below)
    utils/             list-state, csv, form-utils, period
  layout/              shell, sidebar, topbar, global search
  features/<feature>/  <feature>.routes.ts (default export) + pages/components/facade
```

## Data access

- Inject the **abstract repository** (`VehicleRepository`, `TripRepository`, …) — never the mock class,
  never JSON imports in components.
- Paged lists: `createQuery(() => ({ …filters, version: repo.changes() }), (q) => repo.list(q))`.
  `query.initialLoading()` → skeleton, `query.error()` → error state with retry, `query.loading()` → `.is-refreshing`.
- Cross-entity lookups / aggregates: `EntityDirectory` (all collections as signals, `plate()`, `driverName()`,
  `customerName()`, `routeLabel()`, `entityLabel()`, `entityLink()`), and `FleetAnalytics`
  (`tripProfitability()`, `profitabilityOf(id)`, `fuelAnalysis()`, `maintenanceCostPerKm()`).
- Mutations go through the repository or a facade; repositories bump `changes()` so every query refreshes.
- Trip status changes MUST use `TripWorkflowService.changeStatus()` (syncs vehicle/driver/trailer status);
  creation/updates via `TripWorkflowService.create()/update()`.
- "Today" is `ClockService.today()` (pinned demo date 2026-10-24), timestamps `ClockService.now()`.

## Money, dates, numbers

- Never concatenate currency symbols. Pipes (all locale-aware, impure):
  `money` (a `Money` in its own currency), `amount: 'USD'`, `reporting` (number already in the reporting
  currency → shown in the user's display currency), `fmtDate: 'short'|'medium'|'long'|'datetime'|'time'|'monthYear'|'month'|'dayMonth'`,
  `relativeTime`, `num: maxDigits`, `pct` (ratio → %), `distance` (km), `volume` (litres). Import `...FORMAT_PIPES`.
- Transactions are always displayed in their **original currency** (`<app-money [value]="x.amount" showConverted />`
  adds the simulated reporting equivalent with its rate in a tooltip).
- Aggregates across currencies: convert with `CurrencyService.sumToReporting()` / `toReporting()` or use
  FleetAnalytics (already in reporting currency), display with `| reporting`, and put
  `<app-simulated-notice />` next to them (`always` when the aggregate itself mixes currencies).
- Calendar dates are `YYYY-MM-DD` strings; timestamps are ISO with offset. Use `core/formatting/date-utils.ts`.

## i18n

- Every user-facing string comes from `core/i18n/resources/pt-MZ/<feature>.ts` (source of truth, Mozambican
  Portuguese, pre-reform spelling as used in Mozambique: *actualizar, inspecção, direcção, facturação*) and the
  matching `resources/en/<feature>.ts` typed with `TranslationOf<typeof source>` (compile error if keys differ).
- Keep the existing keys of a feature file (enum vocabularies such as `trips.status.*` are used across features)
  and add new ones. Shared strings live in `common.*`, `validation.*`, `entities.*`, `countries.*`, `currencies.*`.
- Templates: `{{ 'trips.fields.origin' | t }}`, `{{ 'common.table.results' | t: { count: n } }}`.
  Plurals: an object with `one` / `other`. TS: `inject(TranslationService).t(key, params)`.
- Enum labels: `'trips.status.' + trip.status | t`. Do not translate ids or enum values themselves.

## UX rules

- No dead buttons: every visible action works (mock CRUD) or is clearly labelled as a demo.
- Lists: search, filters, sortable columns, pagination, loading / empty / no-results / error states, CSV export where useful.
- Mobile: tables become cards automatically via `data-label`; filters wrap; primary action stays in the header.
- Projected content is instantiated by the parent even while a modal is closed: always wrap forms rendered
  inside `app-modal` in `@if (open())` so each opening creates a fresh form with the right record.
- Forms in drawers (`app-modal variant="drawer"`) unless the workflow is long (trip creation is a full page).
- Deleting asks for confirmation; success and failure give a toast.
- Status is never colour-only (badges carry text). Interactive elements are keyboard reachable with visible focus.
- Fuel warnings are "to review", never accusations of fraud. Simulated currency conversions are always labelled.
- Contribution margin ≠ net profit; label actual / estimated / allocated values explicitly.

## Query-param conventions (deep links from dashboard, notifications, search)

`/vehicles?status=&type=` · `/drivers?status=` · `/trailers?status=&type=` · `/customers?status=&segment=` ·
`/trips?status=a,b&customerId=&vehicleId=&driverId=` · `/trips/new?vehicleId=&driverId=&customerId=` · `/trips/:id`, `/trips/:id/edit` ·
`/fuel?vehicleId=&tripId=&warnings=1` · `/expenses?approval=&category=&vehicleId=&tripId=` ·
`/maintenance?status=overdue|scheduled|in_progress|completed|cancelled&vehicleId=` · `/documents?status=&type=&entityType=&q=` ·
`/notifications?category=` · `/profitability?groupBy=trip|customer|vehicle|route` · `/reports?report=` · `/settings?tab=`.
Detail pages: `/vehicles/:id`, `/drivers/:id`, `/trailers/:id`, `/customers/:id`, `/trips/:id`.

- `npx ng build --configuration development` must compile without errors or warnings.
- `npx ng test --watch=false` runs the Vitest unit tests.
- Regenerate fixtures with `node tools/generate-mock-data.mjs` (deterministic).
